is disabled and BN uses running statistics [12].

A persistently decreasing training loss accompanied by a rising validation loss can indicate 
overfitting. Individual fluctuations are not conclusive, and training loss can exceed validation loss 
because training uses augmentation and dropout. Early stopping limits unnecessary training by 
monitoring whether validation loss improves sufficiently [1, Sec. 7.8].

Initialize 𝑟0 = +∞ and 𝑞0 = 0 . Training stops when 𝑞𝑡 ≥ 𝑃 and 𝑃 > 0 ; patience 0 disables this

example, after accepting loss 0.5000, a new value must be below 0.4999 to reset the counter. 
Smaller changes are compared against the unchanged reference in subsequent epochs [12].
Stopping and checkpoint selection are separate. The current configuration saves the highest 
validation-accuracy checkpoint, using lower validation loss to break ties. Improvements smaller than 
min_delta can still update that checkpoint. Evaluation explicitly loads the saved checkpoint; early 
stopping itself does not restore the in-memory model. The learning-rate scheduler also monitors 
validation loss, but uses its own patience setting [12].
